# Sillan CRM — CRM торговых представителей

Внутренняя B2B CRM компании Sillan (оборудование для СТО): база автосервисов и других точек, импорт выгрузок 2GIS, распределение клиентов между торговыми представителями, планы посещений и результаты визитов, заявки в отдел оборудования и отдел запчастей, потенциальные сделки, дашборд и аналитика.

Интерфейс на русском, валюта — тенге, основной рынок — Казахстан (страна хранится в каждой точке, другие страны и города не запрещены).

## Стек

| Часть | Технологии |
|---|---|
| Интерфейс | React 19 + TypeScript, Vite, Tailwind CSS 4, TanStack Query, React Hook Form + Zod, lucide-react |
| Данные и вход | Supabase: PostgreSQL, Auth, Row Level Security, Storage |
| Миграции | `supabase/migrations/*.sql` (в репозитории) |
| Импорт/экспорт | PapaParse (CSV), ExcelJS (XLSX) |
| Тесты | Vitest, Testing Library; тесты базы на настоящем PostgreSQL; сквозные — PostgREST + Chromium |

Права доступа проверяет **база данных** (RLS и функции `app.*`), а не интерфейс: скрытые кнопки — только удобство.

## Что нужно настроить (один раз)

### 1. Проект Supabase

1. Создайте **новый** проект на [supabase.com](https://supabase.com) (регион — например, Frankfurt).
2. Примените миграции — любым способом:
   - **SQL Editor (проще всего):** откройте файл `supabase/all_migrations.sql`, вставьте целиком в Supabase → SQL Editor → Run. Это все миграции по порядку, только для нового пустого проекта.
   - **Supabase CLI:** `npx supabase link --project-ref <ref>` → `npx supabase db push` (применит файлы из `supabase/migrations`).
3. **Authentication → Sign In / Providers → Email:** включён. **Отключите «Allow new users to sign up»** — сотрудников создаёт администратор.
4. **Authentication → URL Configuration:** Site URL и Redirect URLs — адрес, где будет открываться CRM (например, `https://sillan-crm.onrender.com`).
5. Хранилище файлов создаётся миграцией: приватный бакет `crm-files` (фото и вложения, до 10 МБ, только изображения/PDF/Office/CSV).

### 2. Первый администратор

1. Supabase → Authentication → Users → **Add user** → e-mail и пароль, отметьте *Auto Confirm User*.
2. Supabase → SQL Editor:

```sql
update public.profiles
   set role = 'admin', is_active = true, full_name = 'Имя Фамилия'
 where email = 'admin@sillan.kz';
```

Дальше пользователей можно создавать из CRM (раздел «Настройки → Пользователи и роли»), если развернуть функцию из шага 3. Без неё — добавляйте пользователей в панели Supabase: они появятся в CRM **неактивными**, администратор активирует их и назначает роль.

### 3. Функция управления пользователями (рекомендуется)

`supabase/functions/admin-users` — создаёт сотрудников, отправляет приглашения, меняет пароли. Ключ `service_role` используется только внутри функции на сервере Supabase и никогда не попадает в браузер.

```bash
npx supabase login
npx supabase functions deploy admin-users --project-ref <ref>
```

### 4. Переменные окружения

Скопируйте `.env.example` в `.env` (локально) или задайте в хостинге:

| Переменная | Где взять |
|---|---|
| `VITE_SUPABASE_URL` | Supabase → Project Settings → API → Project URL |
| `VITE_SUPABASE_ANON_KEY` | там же, ключ `anon` / `publishable` (его можно использовать в браузере — данные защищает RLS) |

**Никогда** не указывайте `service_role`/`secret` ключ в переменных `VITE_*` — они попадают в браузер.

### 5. Развёртывание

**Render (как Barter Box):** New → Blueprint → выберите репозиторий — подхватится `render.yaml` (статический сайт, деплой из `main`). В Environment задайте две переменные из таблицы выше. Сайт пересобирается при каждом изменении `main`.

Подходит любой статический хостинг (Netlify, Vercel, Cloudflare Pages): команда сборки `npm ci && npm run build`, папка `dist`, все пути переписывать на `/index.html`.

## Локальный запуск

```bash
npm ci
cp .env.example .env   # заполните URL и anon-ключ проекта Supabase
npm run dev            # http://localhost:5173
npm run build          # проверка типов + production-сборка в dist/
```

## Как устроены данные

- **Компания (юрлицо)** и **точка обслуживания** — разные сущности: у компании может быть несколько точек; точка может быть и без компании.
- Направления, услуги, оборудование, контакты, фото — отдельные связанные таблицы (многие-ко-многим), а не строки через запятую.
- **Адрес из источника** (обновляется импортом) и **подтверждённый адрес** (вносит менеджер, импорт его не трогает) хранятся отдельно.
- Ничего важного не удаляется бесследно: клиенты, контакты, оборудование, комментарии архивируются; изменения пишутся в **журнал действий** (вкладка «История» в карточке), смена ответственного — в **историю назначений**.
- Повторная отправка форм не создаёт дублей: заявки, сделки, новые клиенты передают одноразовый ключ (`client_request_id`); добавление в план, перенос визита, результат визита — идемпотентны.

## Импорт из 2GIS (CSV/XLSX)

Встроенного парсера 2GIS в первой версии нет: данные собираются отдельно (допустимым способом) и загружаются файлом. Автоматический сбор с обходом защиты 2GIS не реализован и не должен реализовываться.

Мастер импорта: файл → выбор листа → предпросмотр → сопоставление столбцов (подбирается автоматически по заголовкам) → проверка → решение по возможным дублям → импорт порциями по 200 строк → журнал с отчётом.

Защита от дублей:
1. тот же **внешний ID** того же источника — точное совпадение;
2. то же **название + город + адрес** (после нормализации: регистр, «ё», «ул.», «пр-т» и т.п.) — точное совпадение;
3. совпал **телефон** или **название в том же городе** — *возможный дубликат*: пользователь решает «объединить / оставить отдельно / пропустить». Одинаковый телефон у разных точек автоматически не объединяется.

Режимы: «только добавить новые», «обновить разрешённые поля» (выбираются галочками), «пропустить существующие». Пустые значения в файле никогда не стирают данные; контакты, комментарии, оборудование, фото, визиты, заявки и ответственный импортом не изменяются. Направления подбираются по ключевым словам в категории и названии (ключевые слова редактируются в «Справочниках»).

## Тесты

| Набор | Что проверяет | Запуск |
|---|---|---|
| `unit` | телефоны, нормализация, разбор CSV/XLSX, сопоставление столбцов, классификация строк импорта, экспорт, сообщения об ошибках, форма клиента (обязательные поля, двойное нажатие, ошибка сервера) | `npm run test:unit` |
| `db` | все 22 сценария ТЗ на настоящем PostgreSQL с миграциями и RLS: роли, прямые запросы чужих данных, импорт и дубли, планы, визиты, заявки, сделки, дашборд; сверка нормализации браузер ↔ база | `TEST_DATABASE_URL=postgresql://postgres@localhost:5432/postgres npm run test:db` |
| `api` | те же запросы, что делает интерфейс, через REST API (PostgREST) клиентом supabase-js | дополнительно `POSTGREST_BIN=/путь/к/postgrest npm run test:api` |
| `e2e` | 17 сценариев в браузере Chromium: вход, импорт и повторный импорт, распределение, карточка, план, результат визита с телефона, заявка, сделка, уведомление, мобильная вёрстка | дополнительно `CHROMIUM=/путь/к/chrome npm run test:e2e` |

Тестам базы нужен локальный PostgreSQL 15+ (суперпользователь): каждый прогон создаёт временную базу, применяет `tests/db/supabase_stub.sql` (имитация схем auth/storage Supabase) и миграции, затем удаляет её. **Рабочая база не используется.**

## Структура

```
supabase/migrations/   схема, RLS, функции, хранилище, справочники
supabase/functions/    admin-users (управление сотрудниками)
supabase/all_migrations.sql   все миграции одним файлом (npm run sql:bundle)
src/lib/               клиент Supabase, ошибки, телефоны, форматирование, файлы, импорт
src/components/        UI-компоненты и каркас (меню, поиск, уведомления)
src/features/          разделы: clients, import, visits, requests, deals, team, analytics, settings, dashboard
tests/                 db, api, e2e
```

## Не входит в первую версию

Встроенные карты и прокладка маршрутов (есть кнопка «Открыть адрес» во внешнем приложении 2GIS), автоматический сбор с 2GIS, синхронизация с 2GIS в реальном времени, интеграции с CRM других компаний, внешние уведомления (почта, мессенджеры) — уведомления работают внутри CRM. Фактические продажи и выручка не считаются: суммы сделок — оценка.
